# Location-Based Beam Prediction with DeepMIMO

Predicting the optimal 5G/mmWave beam for a user using **only their (x, y) location** — no channel feedback required — trained and evaluated on real ray-traced propagation data from the [DeepMIMO](https://www.deepmimo.net/) dataset.

![Beam prediction accuracy vs baselines](beam_prediction_results.png)

## The problem

Millimeter-wave and massive MIMO base stations pick from a large "menu" of possible beam directions to serve each user. The standard way to find the best one is **exhaustive beam sweeping** — testing every beam in the codebook — which adds latency and signaling overhead, especially as codebooks grow and users move.

This project asks a simple question: **if a base station only knows a user's rough location (which nearly every phone already reports), can a small ML model predict the right beam well enough to skip most of that search?**

## Approach

1. **Dataset**: DeepMIMO's `asu_campus_3p5` scenario — a ray-traced simulation of a real university campus at 3.5 GHz, covering 131,931 user locations around 35 buildings, generated by an actual physics-based ray tracer (not a statistical channel model).
2. **Beam codebook**: 16 candidate beams built from array steering vectors (ULA, half-wavelength spacing), spanning a 120° azimuth field of view.
3. **Labels**: For every user, the true optimal beam was computed by exhaustively projecting their real multipath channel onto all 16 beams and taking the one with maximum received power — an idealized "genie" beam selector.
4. **Model**: A small 2-layer MLP (`scikit-learn`), input = `(x, y)` position only, output = predicted best beam (16-class classification).
5. **Baselines**: random guessing and always-predict-the-most-common-beam.

## Results

| Method | Top-1 Accuracy | Top-3 Accuracy |
|---|---|---|
| Random selection | 6.2% | 18.8% |
| Majority-vote baseline | 48.3% | 48.3% |
| **Proposed MLP (location-based)** | **74.8%** | **94.2%** |

The model beats the majority baseline by **+26.5 points** using nothing but location, and gets the right beam in its top-3 guesses **94.2%** of the time — meaning a real system could shrink its beam search from 16 candidates down to 3 with very little accuracy loss.

### Ground truth vs. predicted beam map

![Ground truth vs predicted beam assignment across campus](beam_prediction_map.png)

The model recovers the large-scale spatial structure well (open line-of-sight corridors, shadowed regions behind buildings), though predicted regions are visibly smoother than ground truth — a small 2-layer network can't fully capture the jagged, building-edge-driven boundaries in the true data.

## Why this matters

Position-only beam prediction is a cheap, deployable complement to channel-feedback-based beam management: no extra signaling beyond what most devices already report, meaningful reduction in beam-search overhead, and it degrades gracefully (top-3 accuracy stays high even when the top-1 guess misses).

## Limitations

- Trained/evaluated on a single scenario and array configuration — generalization to other environments, frequencies, or array geometries is untested.
- Azimuth-only, 16-beam codebook — no elevation steering, and a simplified array vs. a full massive-MIMO array.
- Position-only input by design; adding cheap side-information (e.g. coarse RSSI) would likely push accuracy higher.

## Reproducing this

```bash
pip install deepmimo scikit-learn matplotlib numpy
python beam_prediction.py
```

This downloads the `asu_campus_3p5` scenario automatically on first run, computes channels, trains the model, prints accuracy metrics, and saves both figures above.

`Python` · `DeepMIMO` (ray-traced channel data) · `scikit-learn` (MLP classifier) · `NumPy` · `Matplotlib`
